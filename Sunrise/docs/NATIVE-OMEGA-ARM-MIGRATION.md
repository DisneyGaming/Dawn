## Requests, application, and identity

1. Startup publishes explicit default `.5` and `.6` records on the first positive boss generation. The active writer predicate requires a positive generation; this does **not** claim a zero-generation retirement body is emitted.
2. A fresh physical boss/fullbody observation requests the intro program. Publication alone cannot bind the boss or complete a clip. The observer requires the desired native member revision, matching authority generation/revision, and the exact native queue before acknowledging application.
3. The first acknowledged program establishes an actor incarnation. Later movement, crown and combat programs advance their native revision while retaining that incarnation for existing graph, motion, scene, and health leases. Observers wait for the new native program before accepting its animation receipts. The final-death health identity path independently resolves native authority through verified read-only `AB27C0`, checks current applied program and physical member revision, and rechecks the actor backlink and both snapshots.
4. Left/right commands claim independent `.5` control only with the current owner and actual zero inputs. A matching native high receipt enables animation observation; actual clip wrap requests low control. Only a matching low application receipt completes the action and enables progression.
5. A movement request requires the exact pending departure or cycle-two final-relocation command. Its native queue revision must be acknowledged before movement receipts are admitted. The motion hook can resolve the current member and authority itself so the first real departure frame is not lost while waiting for the next member callback. Native selector destination, departure/relocation/arrival stages, cleanup, and actual world position remain required.
6. Cancellation publishes low arm control. A pending program can be cancelled with a new empty-program revision; an already applied program is not gratuitously replaced. Reset clears both server ledgers. Run, generation, salted actor, character, entity, fullbody, incarnation, and command epoch fence requests and receipts.

The active member is 223 bits with both defaults, 392 bits with a named program and default arms, and 520 bits with a named program plus owned arm rows. Legacy callers retain their independently tested optional-field behavior.

## Remaining native-boundary findings

- **Health, damage and immunity:** `B804E0` performs the damage transaction; `CDCB60` gates its lethal branch. Runtime health interface `80804BEE` has 50 callbacks at `1CE7650`, with no established dynamic-authority consumer. `CDE390` is the reflected flag setter for health `+338` bit 1; `CDE1F0` changes region behavior. Neither establishes a server health transaction. The peer currently decodes established messages without an external simulation body and routes group control only. Replacement still requires simulation entity ownership, baseline, and the actual health transaction receiver. Existing boss-floor, cube, module, lens and other damage protections remain.
- **Eye/provider values:** `CF9087D3` and intro `CE0BA42D` use parent-provider `A0FE60 -> A10180 -> 5906A0`, including dirty notification. Native scalar control and kind-7 channel actions ultimately use `576420`; that exported-variable path is not proven equivalent to the parent provider. The provider setter is registered as reflected method `47616167`; no authority producer for that method has been established. These local calls remain.
- **Remaining movement boundary:** Panoptes teleport dispatch is migrated as described above. The intro and combat stop helpers still use native event removal and wait for actual retirement. Hijacked uses authored type-47 destination points. Original `4FFEC0`, called by targeted kind-9, accepts type 48 or 58 and rejects type 47; `A97800` does not safely tolerate a failed target resolution. Hijacked has no suitable authored type-48 route. Reusing this codec for those points would therefore be unsafe without an independently proven path/target creation contract; its direct movement command remains.
- **Event and named-child lifecycle:** the migrated named queues do not replace scoped `C620F0`/`C693F0` event references or `C66590`/`C6FE70` child lifetimes used by shield, eye, stun and exit mechanics. Their reference ownership and completion observations remain required.

Native member/fullbody/graph hooks still observe real application and animation receipts, and the retained calls above still perform their existing behavior. The strict current-program check in the health helper admits final native-death receipts only; the B804E0 immunity/floor filters do not call it, and regional health sampling uses the independent character/health identity. A pending program does not disable damage protection.

No publication is treated as fabricated playback, damage, motion, or completion evidence. Installation and live acceptance of this active migration must be reported separately from these offline tests.
