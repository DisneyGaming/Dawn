# Garden platform authority and remaining adapter audit

Dendron's platform movement now uses the already compiled native type23 publication exclusively. The active `garden_cycle::after_update` no longer calls `DF6C70` for first travel, parking, return travel, or death freeze. Its selector/animation actions are separate retained behavior; this change does not claim to remove the whole character-update detour.

## Active production path

`Sunrise.vcxproj` compiles `state/activity/strike_bond/controller.cpp`, `runtime.cpp`, `client/hooks/bootflow/omega_enemy_lair_receipts.cpp`, and `middleware/bap/activity_message/activity_sensor_auth_bodies_other_missions.cpp`. The roster publisher calls `strike_bond::snapshot`. That snapshot consumes the bounded latest platform observation, runs the mission controller, and supplies `Snapshot.strike_bond` to the compiled authority encoder. `strike_bond/authority.h` case23 emits the existing147-bit position-only record for registry `2CB86C0F`, slot173. This targets the authored platform source `80F5493B`, type4 slot172, and native generic device `80F45988`.

The other direction is also active: `omega_enemy_lair_receipts.cpp` includes `strike_bond_fire_trace.inl` and `strike_bond_boss_cycle.inl`. The installed `BCD330` character-update hook invokes `garden_cycle::after_update`. Its sampled platform component goes through `observe_boss_platform_motion` into a fixed latest observation slot under the runtime mutex. The server snapshot authenticates the boss and platform identities again before accepting it. Sampling does not call a setter or move a platform from the server thread.

## Command sequence

The server owns the shortest visual turn. When the current input is more than a quarter-range from the target, it first publishes the equivalent phase half a range away with snap enabled. That phase is visually equivalent because the authored platform spans two revolutions. It waits for the exact native command revision plus matching current and target position before publishing the smooth destination at the next revision. Repeated snapshots and stale acknowledgements cannot skip that boundary or keep increasing the revision.

When no phase rebase is required, the server publishes the smooth destination immediately. Desired target changes select a new plan. Death cancels the travel plan and publishes the observed current position with snap enabled. The local death-animation adapter waits for that exact native stop publication to be acknowledged before requesting the existing native clip. Native damage/death receipts remain necessary; no time or position sample invents death.

Native current `+370`, target `+37C`, position revision `+960`, and velocity `+374` are sampled under the existing full component/source/actor identity checks. Native snap itself writes current/target but does not directly clear `+374`, so snap acknowledgement does not incorrectly require that derivative to become zero. The pre-existing parked-event stillness check remains unchanged.

## Other investigated paths: retained behavior and concrete limits

* Garden intro/sleep/wake/death selector actions: the active adapter calls named action add/remove `C620F0/C693F0` using actor-specific group `AFB11A12`, and burst event `104DA00`. The existing scene authority can address authored scene events, but no equivalent authority producer/consumer for these post-scene character-controller named actions was established. Those calls remain. The weapon target adapter also retains its narrow `C613E0/C5FEF0` slot repair and cached-action replay; no proved server field for that decoder output was found.
* Dendron shield presentation: the active shield adapter owns model pass7's base bit and native draw publication `1150420`, plus blue-shell parent input `0958590C` through `A0FE60`. These are model/material contributions, distinct from already native type26 guardian shields. In the pinned callback registrations around model `1CCEB80..1CCEC00`, mesh-cloth `1CCED60..1CCEDE0`, and parent provider `1CBD440..1CBD8F0`, no matching generic dynamic-authority callback signature `5B937938` was found. No alternate authored source/receiver was verified for these selective semantics. This is a bounded negative finding, not a claim that every engine path was proved impossible.
* Garden tethers: active `omega_arc_charge_receipts.cpp` includes `strike_bond_tethers.inl` and calls its creation wrapper from the installed source constructor. It temporarily substitutes a beam entity for an authored anomaly, then uses `559A00` to follow real cube/guardian endpoints and retains visibility cleanup after source retirement. The generic position record proves an existing component scalar channel, but does not encode replacement entity class or the independently composed beam endpoint transform. A source-retirement packet alone also does not establish equivalent retained-entity hiding. These behaviors remain, rather than being mislabeled as solved by the scalar record.
* Garden carriage: active character update uses authenticated socket `9F6DB313`, bone1, native interface resolution and keep-world attach `5693E0`. Existing source/device authority does not encode that complete hierarchy attachment. No verified server attachment field/receiver was found, so this stays local.
* Garden corpse cleanup: native death detaches Dendron from its source. The server already publishes source/member retirement, while `strike_bond_boss_retirement.inl` retains the captured actor/entity lease and calls native `56A8F0` at the valid allocator/source-retirement boundary. Removing it requires a verified authority route that still identifies the detached corpse, which was not established.
* Hijacked placement/cleanup: active `hijacked_placements.cpp` resolves authored table/record/GUID rows, invokes the native constructor only in the owning bubble context, and qualifies original pose providers before admitting source readiness. Existing source authority does not itself materialize those missing named-point rows. Cleanup/backtracking also uses the native unload boundary and allocator context for detached instances. No equivalent authority record for those table-specific lifecycle actions was verified; all working handlers remain.

## Extended native health, placement and peer audit

The follow-up audit checked both activity authority and the gameplay peer route. It did not remove another behavior hook or introduce a speculative wire record.

`mission_native_authority_inventory_tests.py` verifies the same pinned image SHA256 before executing any original instructions. It enumerates all24 direct generic-record callback registrations in `1CB0000..1D30000`, verifies the health interface's complete50-method registration (`80804BEE`, registration `3265980`, table `1CE7650..1CE7970`), and confirms that this interface has no generic `5B937938` callback. This limits only that channel; it does not prove that no other native simulation protocol exists.

The real health setter `CDE390` is exposed as reflected method `116D45DE4`. Original instructions `CDE390..CDE3B2` change only health `+338` bit1 and issue dirty notification for a bound entity. The test executes512 combinations of existing flags and requested values, then original `CDCB60`, proving preservation of all other bits and the inverse lethal-branch result. This does not establish immunity before `B804E0` side effects or a fractional per-hit floor. `CDE1F0`, another reflected method, changes `+6FA` bit0 and invokes regional `B8DFD0`; no authority producer for it was established. A reflected method entry is not itself a network command.

The gameplay server has no health/damage decision intake at present. Compiled `server/gameplay/peer/peer_transport.cpp` calls `decode_established(payload,false,packet)` and handles reliable connection/group messages. `middleware/gameplay/peer/established_packet.cpp` stops after the two reliable queues, exposing `externalBitOffset` for an external simulation payload without decoding it. A faithful replacement through that separate network would require the simulation entity ownership/baseline grammar, damage transaction request and native replication consumer. Existing group membership and a current-health scalar do not supply these semantics.

The original source constructor `9EFBC0` also narrows the placement alternative. At `9EFCD4..9EFD26`, the active placement override either resolves a scoped placement through `5012E0`, or copies only XYZ from source `+1A0` into the candidate placement `+20`. The executable test runs that latter original branch and proves it preserves the authored entity class, quaternion and scale. The disabled override preserves all48 bytes. Installed anomaly sources `80F544FA`, `80F544F7`, and `80F549F2` each contain exactly one candidate at `+580`, class `80C00F38`; no beam alternative can be selected by their native candidate index. Consequently this override does not replace the active tether class substitution, endpoint-derived rotation/scale, or ongoing follower. No fabricated candidate or transform field was published.

Validation: `python Sunrise/unit/mission_native_authority_inventory_tests.py` passes the callback inventory,512 native lethal-bit cases and native placement branch checks. Its native dirty notification and scoped-reference validity lookup are isolated stubs; it does not execute a live damage transaction, renderer, gameplay peer, or multiplayer session. Disassembly evidence is written under `build/unit/native-garden-platform/evidence/health-methods.txt` and `source-placement-override.txt`.
