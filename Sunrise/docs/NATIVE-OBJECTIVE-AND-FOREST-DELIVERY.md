# Native objective and Forest delivery

## Objective delivery

A Deadly Trial and Hijacked now publish objective installation, replacement, marker references, marker display mode and retirement through the existing native type68 / 80804F67 receiver. Their client presentation callbacks no longer copy event, variant, lifecycle or target fields, call the checkpoint installer, or call the objective retire/build helpers. They report exact native component/content readiness to the mission runtime.

The compiled path is each mission runtime snapshot -> its authority.h -> native_presentation::objective -> the ordinary sensor authority publisher. Readiness comes from the existing directive tick callback, after the original tick, with the definition, schema, offset and resolved self handle checked. The run/incarnation is checked again under the runtime mutex. New runs discard readiness; invalid handles and old owners are rejected. The server withholds objective bodies until content and its manager are ready.

Native1009C00 copies a body even when content is absent. Replaying that same event after loading can therefore miss its installation. ObjectiveDelivery coalesces physical component changes and readiness recovery, rotating the native three-record ring once at the next publication. Logical objective changes use the same rotation. Original1009C00 retires the previous active slot and installs the selected slot; replaying the same publication does not reinstall it. The authored variant at record+4 stays zero: it is an unchecked content-array index, not a transport revision. Marker display mode2 is delivered at record+64; the separate enum at+58 remains zero. All inactive ring slots carry canonical absent events and targets.

Trial's existing waypoint position correction remains. It follows the selected record and its corresponding point at component+480+selector*200. The user-confirmed EC47 walkway height is a deliberate correction to authored data; no native source for an arbitrary point XYZ override has been proved. Omega's separate fallback waypoint/Forest route-hint correction also remains. This migration does not claim all navigation adapters were removed.

`native_mission_dialogue_tests` exports actual Trial/Hijacked dialogue and objective bodies and checks delivery ownership, loading, repeated snapshots, physical replacement, recovery churn and retirement. `tools/coo/verify_mission_objective_native.py` replays those bodies through unchanged1009C00,10098C0,1009ED0 and100A110 in the pinned unpacked image. It verifies all three ring slots, both native manager branches, cold-content recovery, canonical authored variant0, marker reference/locator/mode and960 repeated applications without duplicate installation. Reflection decoding, content lookup, UI record construction, UI/HUD managers and viewer lookup are explicitly modeled boundaries. This is not a rendered HUD or live network playtest.

The separately verified dialogue migration removes direct Trial/Hijacked row-buffer repairs. Original1009B60 applies their real server-produced80804F77 bodies;100A180 dispatches each selected row once while preserving its native processed-generation mirror. `tools/coo/verify_mission_dialogue_native.py` covers25 rows and1,000 duplicate applications.

## Forest generation

Omega and both Beyond Infinity traversals now publish their seeds, four anchors, enable state and zero topology inputs through native type37 / 80805007. Shared `coo/native_mission_forest_authority.h` selects the mission recipe. Omega's archive Snapshot carries the run-derived seed and its actual compiled encoder writes the recovered1750-bit activation body. Beyond's controller owns its pass/seed and authenticates switch-readiness observations before enabling its exact8E70632B/37/3 source. Changing pass clears readiness; a stale run, incarnation or other pass cannot enable it. Garden already publishes the same native zero topology inputs.

Removed active automatic behavior: the FF2F80 solver detour, Omega's direct cached worker seed/anchor writes and source ignition, and Beyond's direct seed/anchor/enable writes. The Forest diagnostic tuner now defaults off; explicitly selected diagnostic controls remain available. The existing owner-authority bitmap repair still runs because native source application does not establish that ownership. No ownership migration is claimed.

`native_generator_topology_tests` exports native recipe vectors, including Beyond's actual mission authority encoder. `tools/coo/verify_generator_topology.py` executes original103E8E0 and10059A0 with unchanged F9CA accessors and checks the effective seed, anchors, enable and solver inputs for seven vectors. The decoder uses independently recovered anchor field offsets, including the nonuniform alignment. It proves source-to-worker application, not procedural output geometry or a live Forest playthrough. Beyond's full route test also covers both pass readiness lifecycles, recovery, seed stability and stale observation rejection. The archive protocol fixture includes type37 and active boss .5/.6 bodies, plus full Forest/boss packets through the compiled preserved-authority publication branch.

## Retained boundaries

Native progression and native delivery are separate claims. Damage transactions, several boss graph/target/model/VFX corrections, dynamic actor cleanup, revival binding, ownership repair, startup and fade still have active client adapters where the required native ownership or network receiver has not been established. See `NATIVE-GARDEN-PLATFORM-MIGRATION.md`, `NATIVE-OMEGA-ARM-MIGRATION.md` and `NATIVE-ACTIVITY-HANDOFF-EVIDENCE.md` for exact evidence and limits. No client engine call moved to a server thread is counted as a native migration.
